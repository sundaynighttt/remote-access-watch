# Remote Access Watch 0.1.0 verification

검증 기준일: 2026-09-02

## 제품 경계

- 독립 저장소와 독립 bundle/launchd identifier를 사용한다.
- 개인 운영 경로, 외부 메신저, 다른 컴퓨터의 런타임에 의존하지 않는다.
- 상태 앱 종료와 root 감시 엔진 정지는 서로 다른 동작임을 UI에 표시한다.

## 자동 검증

- Python 정책 및 상태 머신 테스트 13개 통과
- Swift 상태 분류 및 schema 테스트 4개 통과
- shell syntax, 정책 검증과 launchd plist lint 통과
- Apple Silicon/Intel universal binary, Developer ID 코드 서명 무결성, 패키지 내부·압축 파일 checksum 검사 통과
- release ledger와 README 동기화 검사 통과
- 접근성 트리와 실제 화면에서 제품명, 버전, 현재 상태, 안전 경계, 설치 위치 확인

## 설치 smoke

`0.1.0 (1)` 패키지를 먼저 `observe` 모드로 설치해 기존 복구 엔진과 충돌 없이 상태 생성이 되는지 확인한 뒤 `active` 모드로 업데이트했다.

- launchd job: 로드됨, 최근 종료 코드 `0`, 60초 주기 실행 확인
- 공개 상태: `active`, `healthy`, engine `0.1.0`
- 네트워크: 기본 경로와 Wi-Fi 인터페이스 `en0`, HTTPS 프로브 정상
- Chrome Remote Desktop: 실행 중
- 미해결 사건과 watchdog stderr: 없음
- 이전 daemon/notifier: 모두 비활성화
- 이전 앱·런타임·plist·로그: root 전용 로컬 백업으로 이동
- 설치 앱: `/Applications/Remote Access Watch.app` 한 개만 실행
- 로그인 자동실행: 이전·개발 경로 등록을 해제하고 `/Applications/Remote Access Watch.app` 한 항목만 등록
- 업데이트: 실행 중 앱을 종료한 뒤 교체하고 최종 설치 바이너리로 재실행 확인

## 서명·공증·외부 처리

- Developer ID Application 서명과 hardened runtime 적용 확인
- Apple notarization 1차 승인 후 앱에 ticket을 stapling하고, 최종 ZIP을 다시 제출해 정확한 배포 바이트의 2차 승인 확인
- 최종 ZIP 압축 해제 후 `codesign --verify`, `stapler validate`, Gatekeeper `Notarized Developer ID` 평가 통과
- 최종 ZIP SHA-256: `7a686b37ca0e594fdcad8a36b9e78542d5b1ce6c5dae8963b2eee29af85a0313`
- 공개 GitHub 프리릴리스: [Remote Access Watch 0.1.0](https://github.com/sundaynighttt/remote-access-watch/releases/tag/v0.1.0)

## 일반 릴리스 승격 전 남은 검증

- 공증된 최종 ZIP을 깨끗한 별도 Apple Silicon 및 Intel Mac에서 설치·업데이트·제거 smoke test
현재 GitHub Release는 공개 저장소의 prerelease이다. 기존 active 설치 smoke는 동일한 `0.1.0 (1)` 코드로 통과했지만, 위의 별도 깨끗한 머신 검증 전에는 일반 릴리스로 승격하지 않는다.
